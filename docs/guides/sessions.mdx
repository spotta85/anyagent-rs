## Opening

```rust
use anyagent::{Runtime, SessionOptions};

let (session, events) = runtime
    .open(&agent, SessionOptions::in_dir("/path/to/repo"))
    .await?;
```

`open` returns two halves that you usually hand to different tasks:

- `Session` — the command handle. Cheap to clone; every clone talks to the same
  engine task.
- `Events` — the stream. One consumer.

### Session options

| Builder | What it does |
|---|---|
| `in_dir(path)` | Working directory for the agent. Required. |
| `configure(id, value)` | Set a config option before the first turn |
| `resume(token)` | Reopen an earlier session |
| `fork_from(token, at)` | Branch a new session off an old one |
| `mcp_server(server)` | Hand the agent one of your MCP servers |
| `permission_mode(mode)` | `Ask` (forward requests) or `AutoApprove` |
| `config_home(dir)` | Use a separate config directory for this agent |
| `quiet_window(dur)` | How long silence may run before completion is inferred |
| `record_wire(path)` | Dump the raw protocol traffic to a file |

`record_wire` is the one to reach for when an agent misbehaves — it captures
exactly what crossed the wire, unredacted (prompts, file contents, command
output — possibly secrets), so treat the file as sensitive.

## One-shot generation

`runtime.generate(agent, options, prompt)` returns text and closes the session.
It requires a new session; resume and fork options are rejected. Permission
requests are denied, free-text questions receive a blank answer, and questions
requiring a choice cancel generation. Any reported tool activity also cancels
generation, including a proposed call that has not executed.

For native Pi, generation launches with `--no-tools --no-session`. Tools are
disabled and the session is not saved. Include context inline in the prompt;
path attachments cannot be opened without tools. Other agents must expose
permission requests to support generation.

## Prompting

```rust
let delivery = session.prompt("add tests for the parser").await?;
```

The `Delivery` tells you what actually happened to that prompt:

<ResponseField name="DeliveryKind::Started" type="{ turn_id }">
  The session was idle; this prompt began a turn.
</ResponseField>

<ResponseField name="DeliveryKind::Steered" type="{ turn_id }">
  A turn was running and the agent supports steering, so it went into the
  running turn.
</ResponseField>

<ResponseField name="DeliveryKind::Queued" type="{ position }">
  A turn was running and the agent can't steer, so it waits. `position` is how
  many prompts are ahead of it.
</ResponseField>

Drop a queued prompt before it starts:

```rust
session.dequeue(prompt_id).await?;
```

That returns `InvalidRequest` if the prompt already started.

### Images and attachments

```rust
use anyagent::Input;

session
    .prompt(Input::text("what's wrong here?").attach("screenshot.png"))
    .await?;
```

Check `Capability::Images` to know how it lands: agents that take images get
them inline; for the rest the attachment degrades to a path reference in the
prompt text, which the agent can read with its own file tools.

## Answering requests

Every `RequestOpened` is answered exactly once.

```rust
use anyagent::{Answer, PermissionChoice, QuestionAnswer, Request};

match request {
    Request::Permission(r) => {
        // r.options is what this agent actually offers — answers outside it
        // are rejected.
        session
            .answer(r.id, Answer::Permission(PermissionChoice::AllowOnce))
            .await?;
    }
    Request::Question(r) => {
        // One QuestionAnswer per question, in order.
        let answers = r
            .questions
            .iter()
            .map(|_| QuestionAnswer::Text("yes".into()))
            .collect();
        session.answer(r.id, Answer::Question(answers)).await?;
    }
}
```

A `RequestClosed` arrives when the request is resolved — including when the
agent withdraws it because the turn was cancelled. Clear it from your UI on
that event, not on your own answer.

## Changing settings mid-session

```rust
session.configure("model", "sonnet").await?;
```

Only ids from `details.config_options` are valid. The change is confirmed by a
`SessionUpdated` event carrying the new `SessionConfiguration` — if you need to
know it landed, wait for that rather than for `configure` to return.

### Fast mode

Use the same boolean for Codex and Claude:

```rust
let options = SessionOptions::in_dir("/path/to/repo").configure("fast", true);
```

The `fast` option appears in `details.config_options` only when the selected
model advertises support. Codex reads its service-tier catalog; Claude reads
`supportsFastMode`, including Opus through the `default` alias. The option
updates when the model changes. No model names are hardcoded.

Both providers support `session.configure("fast", true).await?`. Codex sends
it with the next turn. Claude automatically resumes with the new launch
setting before the next turn, keeping the same `Session` handle and conversation.
An active reply finishes normally; background tools delay the resume until a
subsequent turn after they finish. `SessionUpdated` confirms the selected value.
Fast mode lowers latency with increased usage or cost. Account access and
provider cooldowns still apply; the boolean records the selected setting.

### Reasoning effort

The `effort` option is the same everywhere it exists: a live select whose
choices follow the selected model. Set it at open or mid-session, and read the
result from `SessionUpdated`.

```rust
// At open
let options = SessionOptions::in_dir("/path/to/repo").configure("effort", "low");

// Mid-session
session.configure("effort", "high").await?;
```

| Agent | Where the choices come from | Live |
|---|---|---|
| Claude | the model's `supportedEffortLevels` | no, creation-only |
| Codex | its model catalog, sent with the next turn | yes |
| opencode | the model's `variants`, sent as `variant` with every prompt | yes |
| grok | the model's `reasoningEfforts`, with grok's labels, set through `set_model` | yes |
| pi | the model's thinking levels | yes |
| Kiro | `low`, `medium`, `high`, `xhigh`, `max`; absent on models without effort (haiku 4.5, sonnet 4.5 and older, deepseek, minimax, glm, qwen, auto) | yes |

Switching the model rebuilds the choices, and a model without any drops the
option; a `SessionUpdated` carries either change. Hermes and qwen expose no
levels and no way to set one, so they have no `effort` option.

Kiro has no wire call for effort: anyagent runs its `/effort <level>` command
as a hidden prompt. A `configure` made while a turn is running waits for that
turn to end, and a prompt sent while the switch runs waits behind it, so
`configure` never fails for being busy. The current level is read back from
kiro's metadata after every turn.

## Cancelling

```rust
session.cancel(false).await?;  // keep the queue
session.cancel(true).await?;   // drop the queue too
```

Cancelling stops the active turn. The session survives, and the next queued
prompt starts unless you cleared the queue. You still get a `TurnEnded`, with
`StopReason::Cancelled`.

## Closing

```rust
session.close().await?;
```

Ends the agent session and waits for cleanup, capped by a grace period.

<Warning>
Processes the agent spawned itself — backgrounded shells, subagents — may
outlive the session. `TurnEnded { background, .. }` names the tools still
running so a UI can show them, but tool ids are not process handles: an app
that must kill such processes needs its own OS-level tracking.
</Warning>

## Capabilities

Check before you call, rather than assuming per agent:

```rust
use anyagent::Capability;

if session.info().details.capabilities.supports(Capability::Steer) {
    // prompting mid-turn will steer instead of queue
}
```

The full set: `Images`, `Resume`, `Steer`, `Permissions`, `Questions`,
`Rollback`, `RollbackFiles`, `Fork`, `Compact`, `SlashCommands`, `Plan`,
`Subagents`, `ContextUsage`, `PlanUsage`.
